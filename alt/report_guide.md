# 보고서·발표 기본 작성 지침 (03_report.docx · 04_presentation.pptx)

요약·분류(⑧)를 쓰는 에이전트가 `synthesis_guide.md`(형식)와 함께 읽는다. 이 파일은 **무엇을 어떤 순서로, 어느 수준으로 말하는가**를 정한다.
근거: 사용자 결정 2026-10-15 (시니어 연구자 관점 검토 의견 1·2차 반영). 다른 주제에도 쓰는 원칙만 적고, 특정 주제의 예는 '예'로 표시한다.

공통 개발·실행 정책은 `agent_guide.md`를 따른다. 보고서의 모든 표(머리글·본문·부록)는 그 문서의 정렬 규칙을 적용한다.

## 사용자 조정 (우선순위)
1. **개인 스타일** `~/.alt/report_style.md` + **이 조사 맞춤** `<run>/project/style.md` — 있으면 `synthesis_input.json`의 `meta.user_style`로 들어온다 (조사 맞춤은 '# 이 조사 맞춤' 아래). 우선순위: 이 지침 < 개인 스타일 < **이 조사 맞춤**.
   단, 아래 "바꿀 수 없는 것"은 어느 쪽으로도 바꾸지 않는다.
2. **장 순서·포함 여부** — `config.yaml`의 `output.report_sections` / `output.slide_sections` (개인 설정 `~/.alt/settings.yaml`, 그보다 이 조사 맞춤 `<run>/project/settings.yaml`의 같은 이름 키가 우선).
   장 이름은 아래 표의 `id`를 쓴다. 빼도 되지만 `purpose`·`method`는 빼지 않기를 권한다 (결과를 어디까지 믿을지 판단 근거).
3. 사용자가 실행 중 "앞으로도 ~하게"처럼 **계속 쓸 취향**을 말하면, 저장 범위가 미정일 때만 개인 스타일 파일에 저장할지 묻는다. 이미 정한 범위는 재확인하지 않는다.

**바꿀 수 없는 것**: 인용 키는 목록에 있는 것만, 지어낸 문헌·숫자 금지, 검토 수준(전문/초록/제목만)을 넘는 단정 금지, 분모 표시.

## 작성 취지 — 연구 동향 인사이트 (사용자 결정 2026-10-15)
- 보고서·발표의 목적은 **주제의 연구 동향에 대한 전문적인 인사이트**를 전하는 것이다. 어떻게 조사했고 어떤 논문이 채택됐는지는 중요하지만 우선순위가 낮아 **부록**으로 보낸다.
- **독자가 논문을 직접 찾아 읽는다고 전제하지 않는다.** 보고서만 읽고도 동향을 이해할 수 있게 쓴다. "먼저 읽을 논문", "확인할 것", "전문 검토 우선 논문" 같은 읽기 목록을 본문에 두지 않는다.
- 인용 키는 **근거 표시**일 뿐이다. 대표 사례는 "무엇이 보고됐는가"를 설명하는 근거로 쓰고, 읽을거리로 소개하지 않는다.
- 초록 기반 조사의 한계는 "해석할 때 유의점"으로 쓰고, 다음 단계(전문 분석)는 에이전트의 작업 계획으로서 부록에만 둔다.
- 용어: 선정 논문 → **핵심논문**, 리뷰 논문 → **문헌조사논문**. '선정 30편'처럼 절차 용어로 부르지 않는다.

## 논리 흐름
**조사 목적 → 발견 → 근거 → 한계 → 후속 조치.** 독자가 5분 안에 ① 무엇을 조사했고 ② 어떤 기술들이 확인되었으며 ③ 이들이 어떻게 다르고 ④ 지금 무엇까지 말할 수 있고 ⑤ 무엇을 먼저 더 검토해야 하는지 설명할 수 있어야 한다.
- **장은 앞 장의 질문을 이어받는다.** 분야별 소개 → 분야 종합 해석 → 후속 검토 쟁점 → 결론의 우선순위로 이어져야 한다. 정해진 항목을 다 채웠다는 사실만으로 완성이 아니다.
- 분량을 늘리기보다 중복을 줄이고 핵심 메시지를 선명하게 한다.

## 장별 역할 — 같은 발견을 되풀이하지 않는다 (사용자 결정 2026-10-15)
같은 편수·발견이 핵심 인사이트 → 분야 간 종합 → 쟁점 → 결론에 반복되면 문서가 길고 밋밋해진다. 장마다 맡는 말이 다르다.
- **편수는 처음 나오는 곳에서 한 번만** 쓴다 (보통 핵심 인사이트). 뒤 장은 그 편수를 다시 쓰지 않고, **새로운 편수**(예: 쟁점의 세부 집계)만 쓴다. 그림에 이미 나온 편수는 "기술 흐름도(그림 1)"처럼 가리킨다 (장 번호는 설정에 따라 바뀌므로 글에 박지 않음).
- 분야 간 종합: 분야를 가로지르는 **해석**(같은 기법, 다른 역할·검증 기준). 편수 없이.
- 후속 검토 쟁점: 관찰은 짧게, 무게는 **해석상 한계와 열린 질문**에.
- 결론: **판단만** ("~가 중심임", "~는 아직 판단하기 어려움"). 수치를 다시 쓰지 않는다.
- 검토 수준(초록·전문)은 문서 앞 검토 수준 줄과 '해석할 때 유의점'만 말한다. 조사 질문·장 요지(`leads`)·결론에 "초록상", "초록만으로"를 박지 않는다 — 전문을 더 읽으면 낡은 말이 됨. 개별 근거가 초록에만 있으면 그 항목에서 "초록상 확인되지 않음"처럼 쓴다.
- 공학적 흐름도는 연구 접근과 문헌 분포 장에 한 번만 둔다.

## 핵심 키워드와 용어 통일 — 처음부터 결론까지 한 줄로 (사용자 결정 2026-10-15)
독자는 장마다 다른 말로 부르는 개념과, 앞 장과 이어지지 않는 결론을 이해하지 못한다. **키워드로 문서 전체를 꿴다.**
- **핵심 키워드 3–5개는 요약 단계(에이전트)가 고른다.** 사용자가 정해 주면(`meta.user_keywords`) 그것을 쓴다. 고르는 기준:
  1. 조사 질문에 답하는 **판단 축**이다 — 기법 이름(GPR, LSTM)·분야 이름(피로 평가)이 아님 (예: "무엇과 비교해 검증했나", "학습 범위 밖에서도 믿을 수 있나")
  2. **2개 이상 분야**에 걸쳐 나온다
  3. 근거(핵심논문)로 뒷받침된다
  4. 결론에서 **한 줄 판단**을 내릴 수 있다
- 키워드마다 쉬운 정의 한 줄(`plain`), 왜 중요한가(`why`), 각 연구에 던지는 질문(`question`)을 쓴다.
- **흐름**: 조사 목적과 범위에서 키워드 상자로 소개 → 핵심 인사이트·분야 간 종합·쟁점·전망의 주장마다 `[키워드]` 표시 → 분야별 대표 연구 끝에 **분야×키워드 표**(칸마다 15자 이내 판단, 근거 없으면 "미확인") → **결론은 키워드마다 한 줄 판단 + 종합 한 줄**.
- 결론의 키워드 판단은 앞 장(분야×키워드 표·쟁점)에서 이미 보인 내용을 요약한다 — 결론에서 처음 나오는 주장을 만들지 않는다.
- **영어 원어 우선** (사용자 결정 2026-10-27 — '흑상자(black-box)' 같은 AI 조어가 이해를 막음): 조선해양 엔지니어가 영어로 아는 용어(black-box, white-box, grey-box, PINN, fine-tuning, transfer learning, self-attention, noon report, data fusion, random split, SFOC 등)는 **영어 원어를 대표 용어**로 쓰고 처음 한 번만 괄호로 짧게 설명한다(`abbreviations`에 '원어: 짧은 설명'을 넣으면 산출물마다 첫 등장에 자동으로 붙음). 국내에서 굳은 한국어(대리모델·부가질량·축동력·해상상태·운동응답·모형시험)는 한국어. **새 한국어 조어를 만들지 않는다.**
- **용어 통일**: `terms`에 대표 용어와 쓰지 말 변이형(동의어·약칭·띄어쓰기 변형)을 정하고, 모든 글(분야 이름·역할 이름·그림 설명 포함)에 대표 용어만 쓴다. 논문 원문 고유명사·모델명은 예외. `check_terms.py`가 산출물에서 변이형을 찾으면 실패한다.
- 키워드 이름과 대표 용어는 같은 말을 쓴다 (키워드가 "검증 기준"이면 본문도 "검증 기준").

## 부록 — 핵심은 글, 나머지는 표 (사용자 결정 2026-10-15)
- 부록은 개조식으로 나열하지 않는다. **핵심 1–3문장의 짧은 글 + 표**로 쓴다.
- 검색·선정 방법: 선정 흐름·분석 편수 기준·검색 한계만 글로, 나머지 사실은 '항목 | 내용' 표. 다음 단계: 반영 현황 한 문단 + '다음 단계' 표 + '전문 분석 대상' 표. 상세 자료 안내: 한 줄 + '시트 | 내용' 표.

## 배경 이론 + 문헌 통계 (사용자 결정 2026-10-15)
글만 나열하지 않고, **주제의 배경 이론(기존 방법) 위에 문헌 통계를 얹은 그림**으로 연구 접근과 문헌 분포 장을 연다. 어느 주제에도 같은 형식으로 쓴다.
- **흐름도+문헌** (`figures/theory_flow.png`): 공학적 흐름 단계마다 기존 방법[일반 개념] → 그 단계에 놓인 분야·편수 → 학습·검증 자료(수치해석·모형시험·현장계측·미기재) 구성. "연구가 어디에 몰려 있고, 근거는 어느 수준인가"를 한 장에.
- **한계→대응** (`figures/limit_response.png`): 기존 방법의 한계[일반 개념] → 데이터 기반 접근(역할)·예측 대상 → 편수·자료·대표 연구 → 확인해야 할 성능. "왜 이 접근이 나왔고 무엇으로 판단해야 하나".
- **기술 계통도** (`figures/tech_tree.png`, 사용자 결정 2026-10-16): 확정 주제·접근법 → 역할 → 분야(핵심논문 편수·대표 연구) → 대표 기법(`subtopics[].approaches`). 보고서에서는 분야 표를 대신하고, 발표는 분야별 장 앞, 배경학습은 큰 그림 다음에 한 장.
- 기존 방법 서술은 교과서 수준 일반 개념만 쓰고 [일반 개념]으로 표시한다. 기관·선급 문서의 조항·번호·수치는 원문으로 확인한 것만.
- 편수·자료 구성은 코드가 논문 키로 센다. 자료 종류는 초록 판독이므로 그림에 그렇게 밝힌다.

## 기본 장 구성
**기본 순서** (`config.yaml output.report_sections`, 사용자 결정 2026-10-15): 조사 목적과 범위(purpose — 핵심 키워드 소개) → 핵심 인사이트(summary) → 기술 흐름과 문헌 분포(landscape) → 분야별 대표 연구(subtopics, 끝에 분야×키워드 표) → 후속 검토 쟁점(issues) → 결론(conclusion — 키워드별 판단) → 부록: 검색·선정 방법과 한계(appendix_method) · 다음 단계 — 전문 분석 대상(appendix_next) · 상세 자료 안내(appendix_excel) → 참고문헌(APA 7판, 알파벳순).

| id | 장 | 중심 질문 | 담는 것 |
|---|---|---|---|
| summary | 핵심 인사이트 | 이 분야 연구는 지금 어떤가 | 조사 질문 한 줄, 주요 발견 2–4, 해석할 때 유의점 |
| appendix_purpose | 부록: 조사 목적과 범위 | | 아래 purpose와 같은 내용 (기본은 맨 앞 purpose — 사용자 결정 2026-10-15) |
| appendix_method | 부록: 검색·선정 방법과 한계 | | 아래 method와 같은 내용 |
| appendix_next | 부록: 다음 단계 — 전문 분석 대상 | | 에이전트가 다음에 본문을 분석할 대상과 보강할 내용 (독자용 읽기 목록 아님) |
| purpose | 조사 목적과 범위 | 무엇을 왜 조사했나 | 연구 문제, **핵심 키워드 상자**, 문제 유형(입력·출력·왜 필요한가 — 서로 같은 지표로 비교할 수 없음), 핵심/확장/제외 범위 (흐름도는 landscape가 있으면 거기에만) |
| summary | 핵심 요약 | 무엇을 알게 됐나 | 기술적 발견 → 해석상 제약 → 후속 검토 (각 2–4개 권장) |
| method | 검색·선정 방법과 한계 | 결과를 어디까지 믿나 | 검색어 원문·검색일·실제 출판 연도, 점수 계산(백분위 기준 집합), 단계별 모집단과 편수, 분석 편수를 정한 방식, 초록 모드 한계 |
| landscape | 기술 흐름과 문헌 분포 | 어떤 문제·방법이 보이나 | 흐름도+문헌, 한계→대응 그림(아래 '배경 이론 + 문헌 통계'), 분야 개관표(역할·편수·문제), 문헌지도 + 그림에서 읽을 수 있는 것 2–3개 |
| subtopics | 분야별 대표 연구 | 대표 연구에서 무엇이 보고됐나 | 분야마다 같은 틀(공학 보고서 전개, 사용자 결정 2026-10-15): 요지 한 줄 → (1) 연구 목적과 방법(다루는 문제·대표 접근·입력→출력) → (2) 주요 결과(확인된 성과) → (3) 종합 및 남은 과제(분야 종합 해석·미확인 사항). 장 끝에 **분야 간 종합**(키워드 태그)과 **분야×키워드 표** |
| issues | 후속 검토 쟁점 | 무엇이 아직 불분명한가 | 쟁점마다 관찰 → 근거 → 해석상 한계 → 전문 검토 질문, 조사 목적과의 관련성으로 우선순위와 이유. 연구 방향은 '관찰된 접근'과 '가설'로 나눔 |
| conclusion | 결론 | 무엇을 알았나 | **핵심 키워드마다 한 줄 판단** + 종합 한 줄(노란 상자). 다음 단계는 부록 |
| appendix_methods | 부록: 선정 논문 비교표 | | 선정 전부 — 역할·관련성·검토 수준 포함 |
| appendix_excluded | 부록: 선정 밖 점검표 | 선정 밖에 중요한 것이 있나 | 관련성은 통과했지만 총점 미달·상한 초과로 빠진 논문(이유 표시), 선정과의 분포 비교 |
| appendix_counts | 부록: 집계 근거표 | 본문의 편수는 어디서 왔나 | 편수 주장마다 기준(자동 집계 / 초록 판독)과 해당 논문 키 |
| appendix_reviews | 부록: 리뷰 논문 | | 용도(범위 보정·기술 개관·전문 우선 검토)와 핵심 3–4편 표시. 선정 논문 통계와 섞지 않음 |
| appendix_adjacent | 부록: 주목할 인접 문헌 | 주제 밖이라도 알아 둘 영향력 큰 연구는? | 관련성은 낮지만 인용·학술지 점수가 높은 연구논문 최대 5편 + 알아 둘 이유 한 줄 (`adjacent_guide`). 본문 근거로 쓰지 않음 (사용자 결정 2026-10-16) |
| appendix_data | 부록: 데이터·벤치마크 | | 접근 상태(논문 언급만 / 공개 링크 확인 / 실제 접근 확인 / 접근 미확인)와 종류 구분 |
| appendix_terms | 부록: 기법·용어 | | AI 기법 설명, 약어표 — 본문 앞에 알고리즘을 늘어놓지 않음 |
| references | 참고문헌 | | 키·서지·검토 수준 |

| appendix_excel | 부록: 상세 자료 안내 | 상세는 어디 있나 | `05_references.xlsx` 시트 목록 한 장 — **기본값은 표 부록 대신 이것** (사용자 결정 2026-10-15) |

- **상세 표는 보고서가 아니라 엑셀(`05_references.xlsx`)에 둔다.** 본문 표는 판단에 꼭 필요한 것만(예: 문제 유형표, 분야 개관표). 논문별 목록·비교·집계 근거는 엑셀 시트로.
- 보고서 본문은 짧게, 같은 정보를 두 곳에 반복하지 않는다.
- 발표는 같은 순서, 장마다 키워드·도식 위주 (`build_pptx.py` 머리 설명의 발표 양식). 본문 슬라이드 한 장에 메시지 하나.
- **개수·분량은 권장값이다** (발견 2–4, 대표 연구 2–3편, 본문 8–10쪽, 전문 우선 5–8편 등). 조사 결과에 맞지 않으면 개수를 억지로 채우지 않는다.

## 읽기 쉬운 문장 — 요지 한 줄 + 짧은 개조식 (사용자 결정 2026-10-15)
- **장·절마다 첫 줄에 요지 한 문장**(`leads`, `subtopics[].lead`): 그 장에서 독자가 가져갈 결론. 40–70자.
- 그 아래는 개조식 2–4개. 각 항목은 **'머리말: 설명'** 형식(머리말은 굵게 표시됨), **한 항목에 한 내용**, 한두 줄(약 80자 이내).
- 괄호를 겹쳐 쓰지 않는다. 예시·약어 풀이·부연을 한 문장에 몰아넣지 않는다 — 필요하면 항목을 나눈다.
- 인용 키는 **대표 순서로** 단다. 본문에는 앞의 3개만 보이고 나머지는 '외 N편'으로 줄어든다 (전체는 엑셀).
- 숫자는 판단에 필요한 것만 쓴다. 세부 수치·목록은 엑셀 시트로 보낸다.
- 결론이 먼저, 근거가 뒤. 독자가 머리말과 요지만 훑어도 흐름이 잡혀야 한다.
- **돌려 말하지 않는다** (사용자 피드백 2026-10-16): 제목·소제목·요지에 '선택한 접근법', '이 분야', '이 주제', '~에서 보이는 것'처럼 틀만 말하는 자리표시 말을 쓰지 않는다. 실제 이름(`names`의 주제·접근법)이나 그 장의 요지로 쓴다. 예: '[원리] 선택한 접근법의 기본 단계' → '[원리] 데이터 기반 방법의 기본 단계'. 슬라이드 소제목도 요지 한 문장(`leads`의 roles·map·matrix·outlook, `background.leads`). 검사: `check_terms.py`(목록은 config `placeholder_phrases`)
- **같은 말을 장 사이에서 되풀이하지 않는다**: 앞 장에 나온 문장(예: 연구 문제)을 다음 장 첫머리에 다시 쓰지 않는다. 고정 안내 문장도 요지(`leads`)와 겹치면 빼고, 끝맺음은 개조식 명사형(~함·~임)으로 맞춘다.
- **번역투 자제** (한국어 출력, 사용자 결정 2026-10-15): 영어 표현을 직역하지 않고 국내 조선해양 엔지니어가 쓰는 말로 쓴다 — 예와 점검은 `synthesis_guide.md` '반드시 지킬 것'. 영문 출력에는 해당 없음.

## 근거 수준 — 사실 / 연구자 해석 / 후속 가설
문장마다 무엇이 논문 결과이고 무엇이 작성자의 판단인지 드러나게 쓴다. 한 문장에 섞을 때도 구분한다.

| 구분 | 의미 | 표현 예 |
|---|---|---|
| 확인된 사실 | 선정 논문 초록·메타데이터에 쓰인 것 | "초록에서 ~로 보고됨" — 예: "특정 검증 조건에서 R²=0.9X로 보고됨 [Kim2025a]" (가상 예) |
| 집계 사실 | 편수 — 분모와 모집단을 밝힘 | "선정 30편 중 N편", "관련성 3점 이상 후보 N편 중 M편"(`meta.candidate_distribution` 숫자만) |
| 연구자 해석 | 확인된 사실을 종합한 합리적 판단 | "이러한 결과는 ~ 가능성을 시사함", "~로 보임" |
| 후속 검토 가설 | 추가 문헌·전문·규칙 없이는 확정할 수 없는 것 | "~ 여부는 후속(전문) 검토 필요" |

- **편수 주장은 근거를 남긴다**: 초록을 읽고 센 편수(예: "현장 계측을 쓴 논문 4편")는 '초록 판독' 기준이며, 해당 논문 키를 집계 근거표에 남긴다.
- **정량 수치**는 그 인용 문헌의 초록에서 같은 예측 대상·지표가 확인될 때만 쓰고, 대상과 조건을 붙인다. 서로 다른 연구의 R²·MAE·계산시간을 조건이 다른 채로 직접 비교하거나 우열을 매기지 않는다. 인용 키가 유효하다고 인용이 맞는 것은 아니다.
- **쓰지 않는 표현**: 집계 근거 없는 '주류·증가 추세·확대·진화·정착 예상', 선정 문헌만 보고 '분야 전체에서 부족'. 연도별 증감을 말하려면 같은 검색 기준의 연도별 편수를 함께 쓴다.
- 초록에 검증 언급이 없는 것과 검증을 안 한 것은 다르다 → "초록상 확인되지 않음". 수집한 자료에 초록이 없으면 "수집 메타데이터에 초록 없음" (출판 페이지에도 없다고 단정하지 않음).
- 분포 그림의 빈 칸(0편)은 "조사 표본 내 미확인"이지 '연구 공백'이 아니다. 여러 분류에 겹쳐 세는 집계는 "중복 포함"을 밝힌다.
- AI 교차 채점 같은 작업 규칙은 재현 가능한 절차일 뿐, 문헌의 적격성이나 평가의 독립적 신뢰성을 입증하지 않는다.

## 기술 설명 — 설명의 기본 단위는 공학적 문제
- 논문을 소개할 때 **무엇을 예측했나 → 왜 그 예측이 필요한가 → 기존 방법의 부담·한계는 무엇인가 → 이 접근이 어떤 역할을 하나**를 먼저 쓰고, 방법·성능 뒤에는 그 **공학적 의미**와 **초록 수준에서 확인되지 않은 점**을 나눠 쓴다.
- 쉬운 설명은 정확성을 버린 단순화가 아니라 **물리량과 문제의 맥락을 보여 주는 것**이다. 기법 설명은 부록(기법·용어)으로.
- 물리량·출력이 다르면 같은 묶음으로 뭉뚱그리지 않는다. 예: 파면 예측 / 파랑기진력 / 운동응답 / 계류하중 / 피로손상 / 극한하중 확률, 계수 / 주파수 응답 / 하중 전달함수.
- 입력과 방향이 다른 문제는 나눈다. 예: 환경·파면 → 하중(순방향) / 계측 → 미지 하중(역문제), 예측 대상(운동응답) / 활용 체계(디지털 트윈).
- 외삽은 종류를 구분한다: **입력 조건 외삽**(학습 범위 밖 파고·형상 등) / **시간적 외삽**(계측하지 않은 기간의 추정).
- 분야(세부 주제)는 조사 주제에 **직접 해당(핵심)** 하는지, 그 결과를 **활용·확장**하는지 표시하고, 확장 분야는 핵심과의 연결을 한 줄로 쓴다. 분류는 논문 정리의 편의가 아니라 보고서가 답하려는 공학적 질문에 맞춘다.
- 실제 조사 표본에 많이 나온 구조물·조건과 그 밖을 구분하고, 적용 대상을 넘겨짚어 일반화하지 않는다.
- 약어는 처음 나올 때 풀어 쓴다 (자동). 반복 설명은 하지 않는다.

## 초록 기반 보고서와 전문 기반 보고서의 기준
현재 읽기 모드에 맞는 기준으로 쓴다. 전문 단계의 기준을 초록 단계에 일괄 적용하지 않는다.

| 항목 | 초록 기반 | 전문 기반 |
|---|---|---|
| 목적 | 분야 파악·문헌 선별·쟁점 발굴 | 기술 타당성·성능·적용 범위 검토 |
| 성능 | 초록에 보고된 수치와 조건 소개 | 산정 조건·데이터 분할·독립 검증 분석 |
| 미확인 사항 | 잠정적 미확인 사항과 후속 질문 | 구체적 기술 한계와 미해결 문제 |
| 연구 제안 | 가능성 있는 세부 주제 추천 | 목표·방법·검증 체계 구체화 |

## 세분화 판단 (절차 ⑧-1)
문헌조사마다 세분화하는 것이 아니다. 아래 기준으로 **필요하다고 판단될 때만** 사용자에게 묻고, 승인하면 진행한다 (SKILL.md ⑧-1).
- 분야(세부 주제)마다 4가지를 본다. 고정 편수 규칙은 두지 않고 근거를 들어 판단한다.
  1. **문헌 충분성** — 그 분야만으로 대표 연구·기술 유형·쟁점을 비교할 수 있나? 검색 상한에 걸려(`meta.query_logs`의 `stopped_at_limit`) 더 찾을 여지가 있나?
  2. **기술적 독립성** — 목적·예측 물리량·입력·검증 방식이 다른 분야와 따로 분석할 만큼 다른가?
  3. **전달력** — 종합 보고서 한 절로는 차이·한계를 설명하기 어렵거나 압축이 심한가?
  4. **독립 분석 가치** — 그 분야만으로 의미 있는 결론과 후속 질문이 나오나?
- 두 가지 이상이 근거와 함께 분명할 때만 `deep_dive`에 올린다. 애매하면 올리지 않는다 (억지로 나누지 않음). 문헌 수가 늘어난 것과 조사 범위가 넓어진 것은 다르다.
- 올릴 때 쓰는 것: 분야, 충족한 기준, 근거(편수·차이), 세부 조사에서 깊이 볼 질문, 시드로 쓸 논문 키. 여러 분야에 걸치는 논문은 편수를 단순 합산하지 않는다.
